## Desktop-v0.47.1 source realignment

The upstream release reorganises the app without changing the intended TLH
fork deltas:

- **Composer:** upstream moves the PromptBox/editor implementation into
  `plugins/composer`, while core retains host surfaces such as `ComposerBox.tsx`
  and `composer-root.tsx`. This is an extraction, not a feature retirement.
  The Worktree default remains in `NewThreadComposer.tsx` and
  `root-compose-environment-selection.ts`; it was preserved and does not need
  reapplication.
- **Navigation:** upstream replaces the old `AppNavRail` implementation with
  `SidebarNavigationHost`, `SidebarNavigationList`, and the navigation rail
  provider. `AppNavRail.test.tsx` is renamed to
  `SidebarNavigationRail.test.tsx`. The TLH navigation delta remains
  `DEFAULT_HIDDEN_SIDEBAR_NAVIGATION_KEYS = []`, so Search threads stays
  visible in both the list and rail surfaces.
- **Upstreamed delta:** the plugin-host-manager start-wait timeout is now in
  upstream 0.47.1 and is retired from the active fork-only inventory above.

## October 2026 runtime security delta

### Source checks

Node development/CI pins and the digest-pinned Modal base use 22.23.4;
compatibility CI uses 24.22.1/26.12.1. Root/npm engines and POSIX, Windows,
and CLI service install checks enforce the corresponding branch floors. The
runtime-security test is a source-level guard for those floors and pins:
`packages/scripts/test/runtime-security.test.mjs`.

The existing runtime-security workflow-pin exception is deliberate: relevant
fork-controlled workflows retain the patched Node floors rather than claiming
that every upstream workflow is byte-identical. Keep the exception and record
it as a fork delta during future intakes.

### Runtime verification

Source checks do not prove the packaged runtime is safe. Electron 44.9.3 and
its lockfile/test expectations provide the eMudhra CA fix, but the full Node
advisory remains blocked by Electron's bundled Node 24.22.0. Retain this
Electron security blocker until a verified Electron release covers the full
advisory. See [platform support](../platform-support.md#desktop-security-limitation-verified-october-21-2026)
for source/runtime limits and operator rollout requirements.

## Deliberately unchanged

The following upstream surfaces are kept identical to upstream to minimise divergence and merge conflicts. Do not rename, rebrand, or remove them without a separately approved ticket.

- **`~/.bb` data directory**
- **Port 38886 (server) and port 38887 (host-daemon)** — per `packages/config/src/runtime.ts`
- **`bb` CLI name**
- **`BB_*` environment variables** — `BB_DATA_DIR`, `BB_SERVER_PORT`, etc.
- **In-app `bb` wording and icons**
- **bb online services** — accounts, Connect, marketplace, and AI gateway endpoints
- **`apps/mobile`** — mobile app and in-app mobile download links

**Running alongside real bb:** set `BB_DATA_DIR` and `BB_SERVER_PORT` to separate values to run the fork alongside an upstream bb installation without data or port conflicts.
