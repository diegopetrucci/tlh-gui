## TLH background visibility contract

TLH background visibility is a fork-owned contract across the server, SDK,
CLI, and built-in UI; it does not define generic provider behavior. While
active, each confirmed TLH run contributes one `ACTIVE` count, including when
it fans out to parallel children; children do not add counts. The CLI owns
`.thread.activeBackgroundAgentCount`, while the other projections expose the
same run state. A parent turn may settle while confirmed background work
continues, so the runtime is retained. Paused work is not running.

A run may later receive a terminal correction with a fresh item identity. The
contract does not promise one permanent row or item, or deduplicated terminal
history. Tracking loss is not cancellation, and Stop is not proof that the
worker terminated. During an edit, refuse the edit when TLH work is known
active or newly observed as unresolved. Pre-existing historical tracking-loss
or unknown workers are not rediscovered and do not automatically block the
edit.

Restart/restored-run rediscovery, cancellation controls, and per-child detail
are deliberately deferred. Missing or stale event-bus data must not create
speculative rows. Wait, push, and workflow completion semantics are unchanged.
Undo means reverting this code change or reinstalling a prior GUI build; it
does not mean changing TLH profiles.

The contract is exercised by deterministic fixtures in the SDK activity, CLI
`thread show`/`thread log`, background banner, sidebar, and timeline tests.
The SDK check is a public type-shape assertion only; runtime count behavior is
covered by the DB, client-core/sidebar, and timeline fixtures.
